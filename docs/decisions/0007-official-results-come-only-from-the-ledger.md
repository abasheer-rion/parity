# Official results come only from pre-registered runs in a tamper-evident ledger

## In plain words

Before we test an idea for real, we write down exactly what we will test and what counts as passing, and we lock that note. The test then runs on a fresh computer, not on anyone's laptop. The result goes into a record book where every page is sealed to the page before it, so if anyone changes an old result, the seals break and everyone can see. Numbers in our reports are copied out of that record book by a program, so nobody can type a better number by hand.

## Context

The easiest way to fool yourself in this kind of research is to run many variations, keep the best one, and forget the rest. The second easiest is to tweak the plan after seeing the result. And once a result is written down, nothing stops someone from editing it later. Published research has all three problems ([RES-0001](../research/0001-reading-list.md#overfitting-replication-and-decay)), and so did the forums and bots we surveyed ([RES-0002](../research/0002-open-source-and-public-results.md#recurring-failure-patterns-with-examples)).

## Decision

**Two kinds of runs.** Anything anyone runs on their own machine is **exploratory**: useful for learning, never cited as a result. A number is a result only if it comes from an **official** run.

**An official run needs a registration first.** A registration is a JSON file in `registrations/` naming the hypotheses, the exact strategies and parameters, the backtest settings, the pass criteria, how many trials were already spent on the idea, and what result would change our minds. Rules the engine enforces before it will run:

1. The registration is committed to git.
2. It is identical to the version first committed. Plans are frozen; a changed plan is a new registration, and the old one stays as a record.
3. The checkout has no uncommitted changes.
4. Even a dry run needs the registration committed, so seeing a result cannot change the plan.

**Official runs happen only on GitHub Actions** (`official-run.yml`), started by hand with the registration id. A fresh machine, a clean checkout of `main`, data fetched at run time.

**The ledger.** Each official run is appended to `ledger/runs.jsonl`. Every entry holds the hash of the entry before it and a hash of its own contents, plus the hash of a full details file in `ledger/runs/`. Editing, deleting or reordering any entry breaks the chain. `parity ledger verify` checks it, CI checks it on every push, and the engine refuses to append to a broken chain. Pull requests may not touch `ledger/` at all.

**Data fingerprints.** Every fetch records a SHA-256 hash of each series' values and one fingerprint for the whole data set. Each ledger entry stores the fingerprint it ran on.

**A release per run.** The workflow publishes a GitHub release named after the run, holding the full outputs, the ledger details and a copy of the exact data used. Anyone can rerun from that data and compare.

**Generated numbers.** Experiment docs show official results only through a `results` block, which `scripts/docs.py` fills from the ledger. The docs check fails if the block is edited by hand, or if it cites a run that does not exist.

**Trials are counted.** Each registration states its prior trials, and the engine also counts every evaluation already in the ledger for those strategies. The higher of the two feeds the deflated Sharpe ratio.

## Consequences

- EXP-0001 and EXP-0002 were exploratory. REG-0001 repeats EXP-0002 officially so its numbers can be cited.
- REG-0002 (the monthly commodity gap, [HYP-0008](../hypotheses/0008-monthly-commodity-gap.md)) was dry-run once before it was committed, which broke rule 4, since that rule did not exist yet. The plan was committed unchanged afterwards. We record this rather than hide it.
- What this does not stop: someone running hundreds of exploratory variants privately, then registering the best. The defence there is the trial count in each registration, the sensitivity test in the gauntlet, and honesty. The only true protection is new data, which is why registered strategies keep being tracked after their registration date.
- The person who owns the repository could still rewrite git history. The GitHub releases and the Supabase copy are independent records that would expose it.
