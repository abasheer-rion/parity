# The desktop app loads the live site and keeps a copy for offline

## In plain words

The desktop app now shows the live website whenever the computer is online, so it always matches parity.endyland.com and nobody has to reinstall to get a new page. The copy of the site inside the app is only used when there is no connection. Then a thin line at the top says "Offline, showing saved copy", and the app goes back to the live site by itself when the connection returns.

## Context

Version 0.1.1 of the app ([DEC-0041](0041-parity-as-an-installable-site-and-a-desktop-app-for-mac-and-windows.md)) showed a copy of the site frozen at build time. Every page merged after the release was missing from it: the Competitors page, the latency dashboard and the payments pages. The owner asked for the app to always match the site.

## Decision

1. **Live first.** Each section opens on its live address: parity.endyland.com for the front page, Verify, Strategies, Research and Account, and the front pages of sim., trade., academy. and lab.endyland.com for Terminal, Trade, Academy and Workbench, as on the web.
2. **Offline in under 3 seconds.** Before the first page the app checks the website for at most 2 seconds. A page that fails to load, or has not started arriving after 1.5 seconds and fails a second short check, opens from the saved copy instead. While offline the app checks every 15 seconds. Reload checks again straight away.
3. **Sign-in.** Live pages keep the session in the website's own cookie on .endyland.com, stored in the app's private storage, so people stay signed in across launches. The website uses the app's own storage for the session only on the saved copy. Sign-in with Google or GitHub still opens in the browser and comes back through a `parity://` link.
4. **Trust.** Only the saved copy and the website's five addresses can load inside the app. Only those pages get the small page bridge (notifications, opening links in the browser), may ask for permissions or may send messages to the app. Pages never get Node or file access. Every other address opens in the browser.
5. **No service workers in the app.** The website's offline workers are not installed in the app, because the saved copy does that job and a worker could hide a dead connection.
6. **No update check yet.** (Replaced by [DEC-0049](0049-the-desktop-app-opens-on-the-log-in-page-with-a-menu-button-and-its-own-controls.md): since 0.2.0 the app checks a public feed of published releases.) The repository is private, so its releases cannot be read without a login. The app does not check for new versions; a new version is still a download from the release page. Since pages are live, a new version is only needed when the app itself changes.

## Consequences

- Website changes reach the app as soon as the site deploys.
- Offline, signed-in pages of the saved copy ask to sign in again, because that copy keeps its own session.
- For testing, `PARITY_LIVE_ORIGIN` points the app at another address and `PARITY_LOG=1` prints each page it loads.
