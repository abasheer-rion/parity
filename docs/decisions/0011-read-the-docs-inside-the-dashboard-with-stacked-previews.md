# Read the docs inside the dashboard, with stacked previews

## In plain words

The docs used to open on GitHub, one file at a time. Now they open inside the dashboard. Point at an underlined word and a small card explains it. Point at a link inside that card and another card opens beside it, as deep as you like. Select any word or phrase and a card lists every doc that mentions it. Press `/` anywhere to search everything at once.

## Context

The owner asked for a reading view that is fast, lets you jump between linked ideas without losing your place, explains terms in a small popup, and shows every other mention of a word. We looked at what already exists before building anything (research on 2026-10-21):

- Only gwern.net has popups that open from inside other popups. Its code is public domain but depends on the rest of that site, so we copied the behaviour, not the code.
- Quartz has hover previews but only one level deep. Fumadocs, Docusaurus, Starlight, MkDocs Material, Observable Framework and Evidence have no hover previews at all.
- Mintlify needs a paid plan for private docs. Obsidian Publish is paid and closed.
- Floating UI (MIT) handles the positioning of nested popups well, so we use it.

A separate docs site would mean a second login and could not show our own charts. Building into the dashboard avoids both.

## Decision

1. A build step (`web/plugins/docs.ts`) turns every doc, the glossary ([REF-0004](../reference/0004-glossary.md)) and the bibliography into one data file at build time. It links each glossary term the first time it appears in each section, turns doc links into in-app links, marks `[@key]` citations, and works out backlinks and where each term is mentioned.
2. The dashboard loads that file after the first page has drawn, so the dashboard stays fast and the reader opens instantly afterwards.
3. Hover cards follow gwern.net's behaviour: a card stays while the pointer is on it or on a card it opened; clicking a card pins it; Escape closes the top card. On a phone the first tap previews and the card's "Open" link navigates.
4. All doc HTML passes through DOMPurify before it is shown, even though it comes from this repo, because markdown allows raw HTML.
5. The site's frame copies Mercury's banking app: a left sidebar with a workspace row, a switch between two areas (Markets and Research), nested items under the active section and a Bookmarks list; a slim top bar with search, the run picker, settings and a profile menu; Mercury-style cards on Home; and a Settings area where the sidebar becomes a settings menu and each page is a list of label and value rows. Tables follow Mercury's 48px rows.
6. Charts merge Mercury and Robinhood. From Robinhood: a big value with a coloured change underneath, no y axis, a dotted line at the starting value, time range tabs (1M to ALL), and scrubbing that updates the header to the date under the pointer; a strategy page reads like a stock page (About, Key statistics, a verdict panel where the order panel would be, and research that mentions it instead of news). From Mercury: the soft gradient fill under the line, the dotted plot background, quiet date labels and the dark tooltip.
7. Dark is the default: a near-black background with a faint grid and soft blue glows, and a single blue accent. A light theme matching Mercury's is available in Settings. Chart colours stay the validated palette.
8. The docs stay the single source. Nothing is edited in the dashboard; `scripts/docs.py` still checks every file ([DEC-0004](0004-docs-are-checked-by-a-script.md)).

## Consequences

- Every doc is in the dashboard's download, so the site must sit behind a login that covers files, not only pages. The Supabase sign-in only hides the pages. Since 2026-10-21 Cloudflare Access (Zero Trust, free plan, personal account) sits in front of `parity-research.pages.dev` and every preview subdomain: only the emails in the Supabase `members` list get in, by a one-time code sent by email, for 30 days at a time. Adding a teammate means adding them in both places.
- The docs download is about 350 kB compressed. If the docs grow past a few megabytes we should split it by type.
- Term linking uses the glossary names plus a short list of aliases in the build step. A term that appears in prose under another name will not be linked until an alias is added.
- The accent colour is our best match for "Invicta blue"; it is one value (`--accent` in `web/src/styles.css`) if it needs changing.
