# Verify is a public page with broker imports, embeds and a citable method

## In plain words

Anyone can now check a trading record at `/verify/` without signing in. The file is still read in the browser and never sent. Signing in is needed only to publish a badge or add a result to the research dataset. Verify reads exports from the common brokers and exchanges, badges can be embedded in four ways, and the method is published at `/methodology/` so people can cite it. This follows the owner's choice on 27 October 2026 to narrow Parity to Verify (positioning record [DEC-0079](0079-parity-is-an-ai-native-verification-platform-for-retail-traders-of-all-sizes.md)).

## Context

- Verify lived only inside the signed-in app at `/app/#/verify` ([DEC-0036](0036-verify-runs-its-checks-in-the-browser-and-holds-daily-prices-only.md)), and read MetaTrader, TradingView and plain CSV only.
- `/verify/` was already taken: it is where every Supabase email link lands, and links already sent must keep working.
- A badge pointed at the method version but there was no public page saying what that version does.

## Decision

1. **One address, two screens.** Every email link already goes to `/verify/?type=...&token_hash=...`. The page now looks at the address first: when the query or hash carries `token_hash`, `type`, `code`, `error`, `error_description` or `access_token`, it loads the existing confirm screen unchanged; otherwise it shows the public Verify page. Email links already sent keep working, and the email templates do not change.
2. **No sign-in for checking.** Uploads and descriptions work signed out, with the same components as `/app/#/verify`, which keeps working. The daily price file stays behind sign-in, so signed out, card 4 says which fill checks it could not run. Publishing and the dataset send people to `/login/` with a link back.
3. **Imports.** CSV exports from Interactive Brokers (Flex and Activity statement trades), Binance (spot and futures), Bybit, Coinbase, Kraken, cTrader, NinjaTrader, Tradovate, thinkorswim and Alpaca join MetaTrader 4 and 5, TradingView and plain CSV. Fills are paired first in, first out into round trips. Layouts we could not confirm against an official export are marked "unverified layout" in the code and on the page. Personal columns and account-identifying order ids are dropped on parse, as before.
4. **Read-only connections are a scaffold, switched off.** An interface for read-only broker and exchange connections exists behind a flag that defaults off. It holds no keys, registers no OAuth app and makes no network call; the page says "Coming later".
5. **Embeds.** The Share step offers the image badge (`/badge/<id>.svg`), an HTML snippet with alt text, Markdown, and a small card at `/badge/<id>/card`. All are GET only, cached and read through `verify_badge_public`, which never returns an owner.
6. **A citable method.** `/methodology/` describes every check as the code runs it, prints the method version and changelog from the code, and gives a citation. [REF-0030](../reference/0030-parity-verify-methodology.md) is the repository copy.

## Consequences

- Trust stays "Self-reported" for every upload; nothing on the page says a broker checked a file.
- Unverified layouts need a real export (synthetic or with the owner's permission) before the label comes off.
- Turning connections on later needs keys, a security review and its own decision.
