# Verify tools and endpoints for AI apps and programs

## In plain words

Parity is now a verification platform for retail traders, through the website, the API or an AI app. An AI app connected to Parity, or a program with an API key, can run Verify three ways:

- **Trades:** a trade list or equity curve, with how many things were tried. Back comes the verdict, one sentence, the five cards, how many tries the result survives, the method version and what could not be checked.
- **Strategy:** one of our tested strategies by id or name, checked on our research numbers with every try we have counted. Or a rule set in words, which returns the closest strategies we have tested.
- **Claim:** a seller's claim in words or as fields such as win rate, take-profit, stop, monthly return and drawdown. Back comes which claims are impossible and which need more data.

Each runs in memory. Nothing sent is stored. The old names keep working.

## Context

- The owner cut Parity's scope to Verify on 27 October 2026 ([DEC-0079](0079-parity-is-an-ai-native-verification-platform-for-retail-traders-of-all-sizes.md)): "AI-native verification platform for retail traders of all sizes".
- The hosted MCP server ([DEC-0051](0051-ai-apps-connect-to-parity-through-a-hosted-mcp-server-and-people-bring-their-own-model.md)) had `verify_record` and `verify_description`, and the API ([DEC-0071](0071-people-make-their-own-api-keys-for-a-versioned-parity-api.md)) had `POST /verify` and `POST /verify/description`. Neither could verify one of our own strategies, and the names did not say what each takes.
- Verify's checks ([REF-0016](../reference/0016-parity-verify-mvp-spec.md)) are TypeScript and already run on the hosted server. The local Python server ([DEC-0025](0025-ai-assistants-get-parity-tools-through-a-local-mcp-server.md)) had no Verify tools.

## Decision

1. **Three hosted MCP tools, listed first:** `verify_trades`, `verify_strategy` and `verify_claim` (`web/src/lib/mcp/verify.ts`). Each description has an example input, so an AI can call it with no other help.
2. **Old names stay as aliases.** `verify_record` runs `verify_trades` and `verify_description` runs `verify_claim`. Their descriptions start "Deprecated: use ...". Their answers are a superset of the old ones, so existing connections do not break.
3. **Three API endpoints** on the same functions: `POST /api/v1/verify/trades` (scope `write:verify`), `POST /api/v1/verify/strategy` (scope `read:verify`, since it reads only our research) and `POST /api/v1/verify/claim` (scope `write:verify`). `POST /verify` and `POST /verify/description` stay, marked deprecated in the OpenAPI file, which is still generated from the route table.
4. **Same limits and log as before.** MCP calls: 30 a minute and 1000 a day per person, each logged without arguments. API calls: the plan limits, 1 MB bodies and at most 5,000 trades or points. Errors are RFC 9457 problem details; an unknown strategy is 404.
5. **verify_strategy counts every try.** It uses the research run's trials plus the strategy search's trials, the same number the Verify page uses, so the luck check is as strict as on the site.
6. **The local server gets two tools.** `parity mcp` adds `verify_claim` (the five claim rules ported word for word to `engine/src/parity/verify_claims.py`, fields only) and `verify_strategy` (the gauntlet verdict and luck check from the latest local report). Checking a trade record runs only on the hosted server and the API; the local server's instructions and tool descriptions say so.
7. **Pages lead with Verify.** `/developers/` opens with one request per endpoint in curl, Python and TypeScript and answers made by running the real checks. `/connect/` and the Claude, ChatGPT and Gemini guides open with what an AI can verify and prompts to copy.

## Consequences

- An AI app or program can verify all three inputs the website takes, with one tool or endpoint each.
- `read:verify` keys can now verify our own strategies. They still cannot send records or claims.
- Reading a claim from the seller's words needs the hosted server or the API; the local server takes fields.
- Files: `web/src/lib/mcp/verify.ts`, `web/src/lib/mcp/tools.ts`, `web/src/lib/api/server.ts`, `web/src/lib/api/openapi.ts`, `web/developers/index.html`, `web/plugins/guides.ts`, `web/src/connect/ConnectApp.tsx`, `engine/src/parity/mcp_server.py`, `engine/src/parity/verify_claims.py`, tests in `web/tests/verify-ai.test.ts` and `engine/tests/test_mcp_server.py`.
