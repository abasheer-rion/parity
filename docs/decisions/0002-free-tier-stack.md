# Use a free-tier stack of GitHub, Supabase and Cloudflare Pages

## In plain words

We picked free tools for everything. GitHub keeps the code, a free database called Supabase keeps the results, and Cloudflare shows the website. We chose Cloudflare over Vercel because Vercel's free plan would block Amanda and Abanish from publishing changes.

## Context

We want hosting, a database and CI/CD at no cost, for three people, on a private repository. We considered Vercel and Cloudflare Pages for the dashboard.

## Decision

| Piece | Choice | Why |
| --- | --- | --- |
| Code and CI | Private GitHub repo on Ayan's personal account, GitHub Actions | Free for private repos within the monthly minutes allowance. |
| Research engine | Python (pandas, numpy, scipy) | The standard tools for this kind of work, and what most papers and open-source projects use. |
| Scheduled data and backtests | GitHub Actions cron job | No server to run or pay for. |
| Database | Supabase free project (Postgres) | Stores results for the dashboard, with row level security and email login. |
| Dashboard | Vite, React and TypeScript, deployed to Cloudflare Pages | Free with unlimited collaborators. Vercel's free Hobby plan does not deploy commits authored by other people on a private repo, which would block Amanda and Abanish. |

The dashboard is a static site. It holds no data itself. It reads results from Supabase only after a team member signs in, so the public URL shows nothing but a sign-in page.

## Consequences

- If we outgrow a free tier we will see it in [REF-0005](../reference/0005-free-tier-budget.md) first, and make a new decision.
- Supabase pauses free projects after a week without activity. The daily research job keeps it active.
- No secrets live in the repo. Keys are GitHub Actions secrets, and locally in the macOS Keychain or an ignored `.env` file.
