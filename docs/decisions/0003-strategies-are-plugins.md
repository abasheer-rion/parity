# Strategies are plug-ins that can be removed at any time

## In plain words

Each trading idea lives in its own file, like a Lego brick. You can add a brick or pull one out without breaking the rest. Every brick is tested the same way, so the comparison is fair.

## Context

We expect most ideas to fail. The engine should make it cheap to add an idea, compare it fairly with everything else, and throw it away without leaving dead code behind.

## Decision

- A strategy is one Python file in `engine/src/parity/strategies/` containing one class decorated with `@register`.
- It only turns market data into target weights. It never trades, sizes for volatility or charges costs. The shared backtester does that the same way for everyone, so comparisons are fair.
- It declares which data it needs, a one-sentence summary, and a link to the hypothesis it tests.
- It can optionally expose its raw signal, which lets the dashboard measure how much predictive information the signal has before any portfolio rules are applied.
- Deleting the file removes the strategy everywhere: CLI, scheduled runs and dashboard.

The step-by-step guide is [GDE-0002](../guides/0002-adding-a-strategy.md).

## Consequences

- Every registered strategy runs in every scheduled batch, so the number of trials we report for the deflated Sharpe ratio is honest by default.
- Strategies that need intraday data or a different execution model (for example news reaction) will need the backtester to grow. We will make that a separate decision when we get there.
