# New site versions reload in place, and only app changes ask for a restart

## In plain words

The desktop app shows the live site, so most updates need no restart at all. When the site deploys a new version, a page that is already open shows a small card: "A new version of Parity is ready", with Reload and Later. Reload keeps the page you are on and puts back what you typed.

The app itself still updates in the background and installs when you quit. It asks "Restart to update" only when the app itself changed. A release that only refreshes the saved offline copy of the site installs quietly.

## Context

- The owner, 28 October 2026: "can we push updates to the app without restarting, just a reload."
- The desktop app loads the live site ([DEC-0048](0048-the-desktop-app-loads-the-live-site-and-keeps-a-copy-for-offline.md)) and keeps every section loaded, so a page can stay open for days on an old deploy.
- Every desktop release asked to restart, including the weekly ones made only because the offline copy of the site changed.

## Decision

1. **A build id.** Each `npm run build` bakes the commit it builds into the code and writes it to `/version.json` (`web/plugins/version.ts`). `/version.json` is never cached (`web/public/_headers`).
2. **The page checks.** In the desktop app and the installed site, a page asks `/version.json` every 5 minutes and when it comes back into focus (at most once a minute), never while hidden or offline (`web/src/lib/siteVersion.ts`). A different id shows the card once per new build; Later hides it until the next build.
3. **Reload in place.** Reload saves the page's typed fields (never passwords or one-time codes, and nothing inside `data-no-restore`) and the scroll position for this tab, reloads the same address, and puts the fields back once the app has drawn them. Nothing reloads without a press.
4. **Release kind.** The release workflow compares `desktop/` with the last desktop release and writes `releaseName: pages` or `app` into the update files (`desktop/electron-builder.config.js`). The app's updater installs a `pages` release at quit without asking, and asks "Restart to update" once per version only for `app` (`desktop/electron/updatePolicy.js`). Checking by hand always answers. A release without a kind counts as an app change.

## Consequences

- A site deploy reaches open desktop windows within about 5 minutes, with one press and no restart.
- Most desktop releases are now silent.
- A deploy of a commit that only changed docs still offers a reload, since the id is the commit.
- Files: `web/plugins/version.ts`, `web/src/lib/siteVersion.ts`, `web/src/pwa/install.ts`, `web/public/_headers`, `desktop/electron/updater.js`, `desktop/electron/updatePolicy.js`, `desktop/electron-builder.config.js`, `.github/workflows/desktop-release.yml`, tests in `web/tests/siteVersion.test.ts` and `desktop/tests/updatePolicy.test.js`.
