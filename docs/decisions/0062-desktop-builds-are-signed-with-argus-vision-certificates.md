# Desktop builds are signed with Argus Vision certificates

## In plain words

From desktop 0.2.2 the Mac app is signed with Argus Vision's Apple Developer ID and notarized by Apple, so it opens without the right-click, Open steps. The Windows app and installer are signed by Argus Vision, Inc. through Azure Artifact Signing. Windows may still warn on the first installs while the signature builds a reputation with SmartScreen; that warning fades over time on its own. The release stops if any signature check fails.

## Context

- Up to 0.2.1 the Mac build was signed ad hoc and not notarized, and the Windows installer was unsigned ([DEC-0041](0041-parity-as-an-installable-site-and-a-desktop-app-for-mac-and-windows.md) item 10). Every computer asked people to confirm the first time, and an unsigned Mac app cannot replace itself, so Mac updates meant a manual download ([DEC-0049](0049-the-desktop-app-opens-on-the-log-in-page-with-a-menu-button-and-its-own-controls.md) items 11 and 12).
- Argus Vision, Inc. already holds an Apple Developer ID and an Azure Artifact Signing account with a public trust certificate profile. Parity uses them as the publisher.

## Decision

1. **Mac.** Signed with "Developer ID Application: Argus Vision, Inc. (NK9MBSZRUF)", hardened runtime, the entitlements in `desktop/build-resources/entitlements.mac.plist`, and notarized with an App Store Connect API key. The disk images are signed too, then notarized and stapled after the build (`desktop/scripts/notarize-dmg.mjs`, which also rewrites their block maps and their hashes in `latest-mac.yml`). The secrets are `CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_API_KEY`, `APPLE_API_KEY_ID` and `APPLE_API_ISSUER`.
2. **Windows.** Signed with Azure Artifact Signing (formerly Trusted Signing): account `argus-signing`, certificate profile `argus-public`, the East US endpoint (`eus.codesigning.azure.net`), subject `CN="Argus Vision, Inc.", O="Argus Vision, Inc.", L=Irving, S=Texas, C=US`. electron-builder signs `Parity.exe`, the uninstaller and the NSIS installer (`win.azureSignOptions`). The Windows job logs in with GitHub OIDC from the `desktop-release` environment as the Entra app `parity-desktop-signing`, which has only the Artifact Signing Certificate Profile Signer role on that profile. There is no client secret. The repository variables `AZURE_CLIENT_ID`, `AZURE_TENANT_ID` and `AZURE_SUBSCRIPTION_ID` turn it on; without `AZURE_CLIENT_ID` the build is unsigned.
3. **Checks.** The release workflow runs `codesign --verify --deep --strict`, `spctl` and `xcrun stapler validate` on each Mac app and disk image, and `Get-AuthenticodeSignature` plus `signtool verify /pa` on the installer and `Parity.exe`. A failure stops the release; a failed Windows build no longer lets a Mac-only release through.
4. **Updates.** A signed Windows app sets `publisherName` to "Argus Vision, Inc.", so it only installs updates signed by that publisher. Signed Mac builds install their own updates. Copies of 0.2.1 or earlier still need one manual install on a Mac; on Windows they update to the signed build as before.

## Consequences

- People install Parity on a Mac with no warnings. On Windows the publisher shows as Argus Vision, Inc., and the SmartScreen prompt becomes rarer as installs accumulate.
- A Windows release can no longer be unsigned once people run a signed build, because their copies would refuse it. The Azure Artifact Signing certificates renew themselves every few days with the same subject, so nothing needs rotating by hand.
- The Apple certificate and API key, and the Azure app, belong to Argus Vision; if Parity gets its own company accounts the identities change in the config and the secrets, and Windows users need one manual install.
