# Keep a written record of decisions, experiments and sessions

## In plain words

We write everything down: what we decided, what we tried, what happened. Each kind of note goes in its own folder, like a filing cabinet with labelled drawers, so anyone can find it later.

## Context

This is a long research project with three people working at different times. Research projects tend to lose track of why something was tried, which settings produced a number, and which ideas were already ruled out. If we ever write a paper, we will need that trail.

## Decision

We keep everything in markdown files in `docs/`, in eight kinds of document:

| Kind | Folder | Use it for |
| --- | --- | --- |
| intent | `docs/intent/` | Why the project exists. |
| decision | `docs/decisions/` | One choice and the reason for it. |
| hypothesis | `docs/hypotheses/` | A claim an experiment can support or reject. |
| experiment | `docs/experiments/` | Exact settings and results of a run. |
| research | `docs/research/` | Notes on papers, code and forums. |
| guide | `docs/guides/` | How to do something here. |
| reference | `docs/reference/` | Facts to look up. |
| log | `docs/log/` | A dated record of a working session. |

Decisions are not rewritten once accepted. If we change our minds we write a new decision and mark the old one `superseded`. Logs are append-only. Experiments record the git commit and command used, so a number can always be traced back to code.

## Consequences

- There is some overhead on every change. [DEC-0004](0004-docs-are-checked-by-a-script.md) keeps that overhead low by checking and indexing the docs automatically.
- The code changelog ([CHANGELOG.md](../../CHANGELOG.md)) covers code. The docs cover reasoning. They link to each other but do not repeat each other.
