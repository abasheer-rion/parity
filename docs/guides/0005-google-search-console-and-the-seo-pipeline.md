# Google Search Console and the SEO pipeline

## In plain words

The public pages, the sitemap and IndexNow already work without Google ([DEC-0023](../decisions/0023-public-pages-search-engines-can-read-and-a-pipeline-that-keeps-them-fresh.md)). To get Google's numbers, the owner has to prove to Google that we own the site, then let our robot account read it. Steps 1 and 2 below are already done. Steps 3 to 5 are left, and take about ten minutes.

## Summary

What already exists:

- Google Cloud project: `parity-endyland-seo`, under the owner's personal Google account.
- Search Console API: enabled in that project.
- Service account: `parity-search-console@parity-endyland-seo.iam.gserviceaccount.com`.
- GitHub repo secret `GSC_SERVICE_ACCOUNT_JSON`: set to the service account's key.
- Weekly job: `.github/workflows/seo.yml` (Mondays, or run it by hand). Until step 4 is done it reports "no_access" and still passes.

## Steps

### 1. Google Cloud project (done)

For the record, this is how it was made. Never paste the key into a chat or a file in the repo.

```sh
gcloud auth login                       # the owner's personal Gmail
gcloud projects create parity-endyland-seo
gcloud config set project parity-endyland-seo
gcloud services enable searchconsole.googleapis.com
gcloud iam service-accounts create parity-search-console --display-name "Parity Search Console"
```

### 2. The key, stored safely (done)

The key was made once and stored as the GitHub secret `GSC_SERVICE_ACCOUNT_JSON`, without printing it. Keep one copy in the vault (macOS Keychain or the password manager) with a row in the credentials register: name, service (Google Cloud), account (the service account above), purpose (Search Console reports), scope (Search Console only), created date and expiry. If a key is ever shown on screen, delete it in Google Cloud and make a new one.

### 3. Verify the site in Search Console (owner)

Open Search Console (search.google.com, then Search Console) with the personal Gmail and add a property. Pick one:

- **Domain property `paritytrading.app` (preferred).** Parity moved there on 26 October 2026 ([DEC-0067](../decisions/0067-parity-moves-to-paritytrading-app.md)). Google shows a TXT record. Add it in Cloudflare DNS for `paritytrading.app` (type TXT, name `@`). Note the current DNS records first, so the change can be undone. This covers every subdomain.
- **URL-prefix property for paritytrading.app** (typed with `https` in front and a slash at the end). Choose the "HTML tag" method and copy only the `content` value. In GitHub, add a repository variable (not a secret) `GSC_VERIFICATION` with that value, then rerun "Deploy dashboard". The build puts the tag in the front page. Click Verify.

### 4. Let the service account in (owner)

In Search Console, open the property, then Settings, Users and permissions, Add user. Enter `parity-search-console@parity-endyland-seo.iam.gserviceaccount.com` with **Full** permission. Restricted users cannot submit sitemaps.

### 5. Run the report

In GitHub Actions, run "SEO report". It submits the sitemap (`/sitemap.xml` on paritytrading.app) and saves clicks, impressions and top queries. The summary is on the run page and in the `seo-report` artifact. It tries `sc-domain:paritytrading.app` first, then the URL-prefix property for paritytrading.app. The old `endyland.com` addresses redirect with a 301; in Search Console, use the Change of Address tool only if an `endyland.com` property was ever verified. To change that, set the repository variable `GSC_SITE_URLS` (a comma list).

### Bing (optional)

In Bing Webmaster Tools, choose "Import from Google Search Console" after step 3. Bing already hears about changed pages through IndexNow after every deploy. For a tag instead, set the variable `BING_VERIFICATION`.

## Good to know

- **Google's Indexing API is not for us.** Google allows it only for job postings and live event pages. Sitemaps are the supported way.
- **The IndexNow key is public by design.** It is the file `web/public/86c7d7885454f6b74980f4cc83667fd6.txt`. It proves we own the site and is not a secret.
- **New pages appear by themselves.** Add a glossary term, a catalog idea or a doc with an "In plain words" section, and the next deploy publishes it, adds it to the sitemap and pings IndexNow.
- **Run it locally:** `cd web && npm run build`, then open `dist/learn/`. `python3 scripts/seo/search_console.py` without the key just says it skipped.
