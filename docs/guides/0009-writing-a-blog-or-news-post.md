# Writing a blog or news post

## In plain words

Run `npm run newsroom:new` in `web/`, write the post in the file it makes, look at it with `npm run newsroom:preview`, then set its status to published and open a pull request. The site checks the post before it builds. If something is missing, such as a source, a picture credit or the Opinion label, the build stops and says what to fix.

## Summary

The rules and the reasons for them are in [DEC-0057](../decisions/0057-blog-and-news-pages-with-labelled-posts-and-real-bylines.md). The copy rules in [REF-0017](../reference/0017-parity-copy-rules.md) apply to every post.

## Steps

1. Start a draft, from `web/`:

   ```bash
   npm run newsroom:new -- --type Analysis --title "What carry paid in 2026" --author parity-research
   ```

   It writes `content/newsroom/drafts/<date>-<slug>.md` with `status = "draft"`.
2. Fill in the front matter between the `+++` lines. The template explains each field.
3. Write the text in Markdown under the second `+++`.
4. Preview it with `npm run newsroom:preview` and open <http://127.0.0.1:4410/blog/>. Drafts show with a banner and are never public.
5. When it is ready, move the file to `content/newsroom/posts/` and set `status = "review"`. Someone else reads it.
6. The reviewer sets `status = "published"`. Run `npm run newsroom:check`, then open a pull request. The post goes live when it merges.

## Choosing the type and the label

| Type | Goes on | Label it must carry | Sources required |
| --- | --- | --- | --- |
| Research | Blog | Fact-based reporting or Analysis | Yes |
| Analysis | Blog | Analysis | Yes |
| Opinion | Blog | Opinion | No, but cite what you argue from |
| Explainer | Blog | Fact-based reporting or Analysis | No |
| News | News page | Fact-based reporting | Yes |
| Company update | News page | Fact-based reporting | No |
| Press release | News page | Fact-based reporting | No |

An opinion piece should also say in its first line that it is one.

## Writing the text

- `## Heading` and `### Smaller heading`.
- Cite a source with `[^id]`, where `id` matches a `[[sources]]` entry. A source with `ref = "mclean2016"` takes its title and link from `docs/_system/references.json`.
- `> [!pull] A line` makes a pull quote. `> [!note] A line` makes a note box.
- `![What it shows](chart:catalog-evidence "Caption")` puts a chart in the text. It also needs an `[[images]]` entry with the same `src` and the alt text.
- Tables, lists, bold, italic, code and links work as usual. HTML is shown as text.

## Pictures

| Kind | Fields | Notes |
| --- | --- | --- |
| A chart from our data | `kind = "chart"`, `chart`, `alt` | Charts are in `scripts/newsroom/charts.py`. Add one there if you need a new picture |
| A stock photo | `kind = "stock"`, `src`, `alt`, `credit`, `licence`, `source_url` | Unsplash or Pexels only, with the photo's page on that site |
| Our own graphic | `kind = "own"`, `src`, `alt`, `credit = "Parity"`, `licence = "Parity own work"` | Put the file in `content/newsroom/images/<slug>/` |

Use photos at least 1600 pixels wide. The build makes the smaller sizes and the modern formats. Never use a picture from a news site, a search result or social media.

## Bylines

Sign with your own id from `content/newsroom/authors.toml`, or with a house byline (`parity-research`, `parity-markets-desk`, `parity-editorial`) when the work is shared. Do not add people who are not on the team. A team member's bio is only what they have done in this repository or what they have given us, and `bio_status` says whether they have approved it.

## Corrections

Fix the text, set `updated`, and add a `[[corrections]]` entry with the date and what changed. Corrections stay on the post.

## Drafts written by a machine

The SEO pipeline can propose a post through `scripts/newsroom/hook.py`. It lands in `drafts/` with `[review] generated_by`. To publish it, a team member reads it, checks every number against its source, and sets `review.approved_by` to their own id and `review.approved_on` to the date. The build refuses it otherwise.
