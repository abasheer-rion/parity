# Free tier budget

## In plain words

What each free service lets us use for free, and how close we are to the limit. So far we use only a small part of each.

## Summary

What each free service allows and roughly how much we use. Limits change, so check the provider's page before relying on a number here. Last checked 2026-10-20.

## Limits and use

| Service | Free allowance | Our expected use | Watch for |
| --- | --- | --- | --- |
| GitHub Actions (private repo) | About 2,000 minutes a month | CI about 3 minutes per push; research run about 3 minutes a weekday, so roughly 70 minutes a month plus CI | Long intraday experiments should run locally, not in Actions. |
| GitHub storage | Repo size should stay small | Data and outputs are git-ignored | Never commit data files. |
| Supabase free project | 500 MB database, pauses after 7 days idle, 2 free projects per account | Each batch is well under 1 MB | The daily job keeps it active. Prune old batches if size grows. |
| Supabase auth email | A few emails an hour on the built-in sender | Three people signing in | Sign-in links can be slow to arrive. |
| Cloudflare Pages | 500 builds a month, unlimited bandwidth and seats | One deploy per merge plus previews | Builds run in GitHub Actions, so only uploads count. |
| FRED | Generous; API allows 120 requests a minute | About 30 requests a day | Use an API key long term. |

## If we hit a limit

Write a decision before paying for anything. The usual fixes are to run heavy work locally, prune old data, or cache more.
