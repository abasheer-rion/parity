# Parity copy rules

## In plain words

How to write the words on Parity's pages. Say what the page shows or does, with real numbers, in short sentences. Leave out slogans, drama and filler. These rules cover every page in the product app, the research app, Parity Terminal, the Academy, Verify, the public pages and the legal page intros.

## Summary

Every line of copy should state a fact a reader can check on the page. If a sentence would still make sense on any other product, cut it. Numbers come from the data the page loads, or the claim goes. The required disclaimer appears once per page. The checks in [GDE-0003](../guides/0003-writing-docs.md) still apply to docs; this page adds the rules for user-facing text.

## Rules

1. **Say what it is.** Lead with what the page shows or does. "Every strategy we have tested, after trading costs" beats a tagline about truth or openness.
2. **No slogans or taglines.** Cut lines such as "in the open", "one method", "the truth about a strategy", "written into how it is built, not just promised" and "graded on a curve".
3. **No dramatic metaphors.** No walls, gauntlets, lie detectors, battles or stories as prose. A feature name stays only if it is the real name in the UI, such as Bot Battle. Otherwise name the thing: "the 11 tests", "the rules that keep the two sides apart".
4. **No "not X, but Y".** State Y. Keep a contrast only when it teaches something exact, such as "count days, not headlines" in an event study.
5. **No rule of three for rhythm.** List items because there are that many, not to make a sentence sound balanced.
6. **No caps labels above headings.** No eyebrow or kicker text over a title. Use sentence case for labels.
7. **Real numbers, not vague sizes.** Replace "thousands", "dozens" and "hundreds" with the real count from the page's data (for example the search's trial count), or drop the size.
8. **Do not invent numbers.** Every number must come from a data file the page already reads, a doc it links to, or the code that computes it. If you cannot point to the source, remove the claim.
9. **No hedging filler or intensifiers.** Cut "simply", "honest", "truly", "really", "exactly", "plainly" and "in plain words" used as decoration.
10. **No em dashes or en dashes.** Use a full stop, a comma or "to" for ranges. Missing values show "n/a". Curly quotes and the ellipsis character are also out.
11. **One disclaimer per page.** Use "Research and education only. Not investment advice." once. If the app footer already shows it, the page does not repeat it.
12. **One idea per sentence.** Split sentences that carry a dash, a semicolon and a bracket at once.
13. **Keep the teaching.** Glossary entries, Academy lessons and explanations stay. Make them plain; do not remove what they teach.
14. **Legal pages.** Only the intros follow these rules. Do not change legal substance.

## Checking copy

1. Search the files you changed for the markers above (gauntlet, honest, thousands, dozens, wall, simply, not just) and for dash characters.
2. Open each changed page in the running app (`npm run dev`) and read the text the page builds at run time, including tooltips and empty states.
3. Run `npm test`, `npm run cls` and `python3 scripts/docs.py check`.
