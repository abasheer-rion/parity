Parity API

Verify a trade record, one of our tested strategies, or a seller's claim from your own programs. The API runs the same checks as Verify on the website and as the Verify tools AI apps use through Parity's MCP server. It also serves our tested strategies, market data and news impact.

Verify reports what a record shows. It gives no advice. Market data is delayed, end of day.

Verify a trade record in one request

Three endpoints, each one POST with a JSON body. Each answers with a verdict (holds_up, could_be_luck, fragile, does_not_hold_up or not_enough_data), one sentence written from the numbers, the method version and could_not_check: the checks your input cannot run, and why. Nothing you send is stored. How each check works: methodology. Every field: /api/v1/openapi.json.

EndpointScopeSend
POST /api/v1/verify/tradeswrite:verifyA trade list or an equity curve, how many things were tried, and whether it is real, demo or a backtest
POST /api/v1/verify/strategyread:verifyThe id or name of one of our tested strategies, or a rule set in words
POST /api/v1/verify/claimwrite:verifyA seller's claim, in their words or as fields such as win rate, take-profit and stop

The answers below were made by running the real checks on these bodies, then trimmed: long lists are cut to one item and some fields are left out.

Trades: POST /api/v1/verify/trades

Send kind (real, demo or backtest), and trades (each with close_time and pnl) or equity (each with date and equity), up to 5,000 rows. Send tries: how many strategies, bots or settings were tried, counting this one. More tries make the luck check stricter. starting_balance turns trades into returns, and claim compares a seller's numbers with the record. Verify needs at least 30 trades or 60 daily values for a verdict.

curl

# trades.json holds 40 trades; the Python example below builds the same file.
# {"kind": "demo", "tries": 12, "starting_balance": 10000,
#  "trades": [{"close_time": "2026-01-05", "symbol": "EURUSD", "pnl": 120},
#             {"close_time": "2026-01-06", "symbol": "EURUSD", "pnl": -80}, ...]}
curl -s https://paritytrading.app/api/v1/verify/trades \
  -H "Authorization: Bearer $PARITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d @trades.json

Strategy: POST /api/v1/verify/strategy

Send strategy: an id or name from our tested list, such as fx_carry or The Gambit. Verify runs on our research numbers with every try our research and strategy search have counted, and adds the gauntlet result (tests passed of 11). Or send description, a rule set in words, to get the closest strategies we have tested, each with an id to verify next. An unknown name answers 404.

curl

curl -s https://paritytrading.app/api/v1/verify/strategy \
  -H "Authorization: Bearer $PARITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"strategy": "fx_carry"}'

Python

r = requests.post("https://paritytrading.app/api/v1/verify/strategy",
                  headers={"Authorization": f"Bearer {os.environ['PARITY_API_KEY']}"},
                  json={"description": "buys the highest-yielding currency and sells the lowest, monthly"}, timeout=30)
for s in r.json()["closest"]:
    print(s["name"], s["verdict"], s["luck_check"])

Claim: POST /api/v1/verify/claim

Send text (the seller's words), claim fields, or both. Fields win over the text. Rates are fractions: 0.92 means 92%. Fields: winRate, takeProfit, stopLoss, avgLoss, monthlyReturn, maxDrawdown, maxLoss, tradesPerMonth, trades, months, leverage, grid, martingale, maxLossCapped. Each claim comes back marked impossible, needs_more_data, loss_not_capped or adds_up, with the sums in words.

curl

curl -s https://paritytrading.app/api/v1/verify/claim \
  -H "Authorization: Bearer $PARITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text": "92% win rate, 5% take-profit, no stop loss"}'

Python

r = requests.post("https://paritytrading.app/api/v1/verify/claim",

The old paths still work: POST /api/v1/verify answers as /verify/trades and POST /api/v1/verify/description as /verify/claim. The OpenAPI file marks them deprecated.

Start in three steps

  1. Sign in, open Settings, API keys and choose Make a key. Pick the scopes you need.
  2. Copy the key. We show it once and keep only a fingerprint, so we cannot show it again.
  3. Send it on every request as Authorization: Bearer pk_test_... to https://paritytrading.app/api/v1/.

The full description is in OpenAPI 3.1 at /api/v1/openapi.json. Load it into Postman, Insomnia or a code generator.

Keys

A key looks like pk_test_ followed by 49 letters and digits. The first 43 are 32 random bytes. The last 6 are a checksum, so a typo is caught at once and secret scanners can spot a real key in code. Keys that start pk_live_ will come with paid plans.

  • Expiry: 90 days unless you pick 30, 180 or 365. Expired keys stop working.
  • Rotate: makes a new key with the same scopes. The old one keeps working for the time you pick (now, 1 hour, 1 day or 7 days), so you can swap without downtime.
  • Revoke: stops a key. It takes up to a minute everywhere.
  • Allowed addresses: optional. List IP addresses or ranges and the key works only from those.
  • Up to 10 active keys per account. The keys page shows each key's last 4 characters, last use, today's requests and a log of what happened to your keys.

Keep keys on your server, in a secret manager or environment setting. Never put a key in a web page, an app you ship, or a git repository.

Every answer carries RateLimit-Limit, RateLimit-Remaining and RateLimit-Reset. Over a limit you get 429 with Retry-After in seconds. The daily count covers all your keys together and resets at 00:00 UTC. POST bodies can be up to 1 MB, and a Verify call up to 5,000 trades or equity points.

TypeScript

const API = "https://paritytrading.app/api/v1";

async function parity<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(`${API}${path}`, {
    ...init,
    headers: { Authorization: `Bearer ${process.env.PARITY_API_KEY}`, "Content-Type": "application/json", ...init.headers },
  });
  if (!res.ok) {
    const problem = await res.json(); // RFC 9457: type, title, status, detail
    throw new Error(`${problem.status} ${problem.title}: ${problem.detail ?? ""}`);
  }
  return res.json() as Promise<T>;
}

const { strategies } = await parity<{ strategies: { id: string; verdict: string }[] }>("/strategies?limit=5");
console.log(strategies.map((s) => `${s.id}: ${s.verdict}`).join("\n"));

Leaked keys

If a key ends up somewhere public, revoke it in Settings. If you cannot sign in, or you found someone else's key, send it to us and it is revoked at once. Holding the key is the proof, so no sign-in is needed:

curl -s https://paritytrading.app/api/v1/leaked-keys \
  -H "Content-Type: application/json" -d '{"key": "pk_test_..."}'

The endpoint also takes GitHub secret scanning's format and answers with each token's SHA-256, never the token.

Security

  • We store only an HMAC-SHA-256 of each key with a server secret, plus its last 4 characters. A copy of our database cannot be used to rebuild or test keys.
  • HTTPS only, with HSTS. Keys are never written to logs. Request logs keep the time, path, status and duration for 30 days, never query strings or headers.
  • Every key event (made, rotated, revoked, leaked) goes in a log you can see on the keys page.
  • Browsers on other sites are refused. The API is for servers.

The design and its reasons: DEC-0071 and DEC-0082 in the Parity repository.
